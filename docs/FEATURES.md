# Feature Specification

**MVP — planned**
- Appliance category selector and searchable issue list.
- Symptom intake with plain-language questions.
- Hazard triage (smoke, burning smell, sparks, gas, shock, flooding near electricity, etc.).
- Rule-based diagnostic decision trees for a few low-risk scenarios.
- Ranked hypotheses with rationale, unknowns and safe observational checks.
- Escalation recommendations and structured session summary.
- Mobile-responsive, accessible UI.

**Phase 2**
- Model number identification and compatibility checks.
- Manual/FAQ retrieval with citations and source dates.
- User accounts and saved diagnostic histories.
- Photo upload for externally visible conditions.
- Evaluation dashboards and reviewer feedback workflow.

**Phase 3**
- Audio classification for narrow, validated sound categories.
- Cross-modal evidence fusion with missing-modality handling.
- Repair log, shareable technician handoff and export.
- Admin-curated diagnostic knowledge base.

**Exploration**
- Video-assisted inspection for safe, external observations only.
- Multilingual UX and speech-to-text.
- Repair cost/parts availability integrations, where reliable.
- Technician directory or booking integrations.

## User-facing result requirements
A result must distinguish: **observations**, **possible explanations**, **confidence/uncertainty**, **safe next steps**, **do-not-attempt warnings**, and **when to seek professional help**.

## Definition of done
Every diagnostic flow has documented coverage limits, hazard tests, reference cases, privacy review, user-friendly error states and evaluation metrics.
