# Safety and evaluation

The app is an evidence organizer with constrained external care guides. It cannot certify safety or infer an internal defect from a photo. Explicit yes/unsure safety responses stop the flow before a provider call. The shared detector covers smoke, fire, electrical shock, gas/refrigerant, exposed/frayed wiring, breaker trips, overheating, melting, arcing, electrical odors and water near electricity. A burnt-toast-only phrase is a benign decoy; any accompanying hazard still escalates.

Generated observations, titles, reasons, uncertainty and unknowns are checked for procedural instructions. A violation falls back to fixed basic guidance. Action-like questions are removed. Vision output is screened too. The provider prompt, schema validation and regex filters reduce risk but are not a proof of safety. Streamed draft hypotheses are provisional; a final hazard result removes them and disables repair guidance.

`npm test` runs the 100+ phrase corpus in evals/hazards.json and requires 100% recall on that corpus and <=2.5% false positives on its benign examples. Those numbers describe only a regression fixture, not population performance. The six-case synthetic retrieval benchmark tests citation pages, empty results and model mismatch. Rules-only has zero source citations; retrieval provides the three supported synthetic page references. Manufacturer/manual diagnostic accuracy has not been benchmarked.

Tests cover API JSON/method/origin/body constraints, no-model safety/basic handling, quota fallbacks, generated-instruction rejection, private camera lifetime, late camera grants, live snapshot cap, device backups/calendar logic, cost/recurrence helpers, model mismatch/invented citations, streaming parsing, dialog skip/recovery and rate accounting. Real Neon tests checked sign-up, token issuance, database round trip, revision conflicts, invalid tokens, and second-account isolation using reserved QA identities. No email was sent.

Physical camera, native share/print UI, browser dictation and install prompts require device-specific checks. No claim of expert certification, calibrated diagnostic probabilities or manufacturer verification is made.

Deployment smoke checks also verified real streamed AI output and safe fallback, PDF extraction/page retrieval, managed auth sign-up/sign-in/sign-out/session restoration, and an offline reload with the preview server stopped. A twelve-way concurrent database reservation test granted exactly five analysis slots. The client UI still depends on device support for physical cameras, speech, native sharing and installation.
